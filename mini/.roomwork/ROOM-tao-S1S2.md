依据:B9b 桃桃档案 + 四主角框架。按 `PLAYBOOK.md` 生产线走,S2 通过 `planlint` 之前不动一行绘制代码。

## S1 立项

### 这间房要说明她的什么

> **她拼命要被看见,而最真的话全在镜头拍不到的地方。**

档案里的分界线是「镜头内 ↔ 镜头外」。这间房的全部设计只服务这一条。

### 分界线的物理形态 ★ 本案关键决策

**镜头侧对,不是正对。** 手机支架立在房间左侧、朝右拍,于是:

- **右半 = 镜头内 = 舞台** —— 观众看到的桃桃
- **左半 = 镜头外 = 证据** —— 她自己的桃桃

玩家是上帝视角,一眼同时看到两半 —— **反差成立在同一屏里**,这是「屋子是人的外化」的正确表达。若镜头正对玩家,镜头外就等于画外,玩家什么也看不到,设计立刻失效。

**分界线由一架屏风实体化**(现状已有屏风,复用):开播时拉开露出舞台,收工后拉上,把证据那半边藏起来。屏风是这间房唯一一件「有状态」的家具。

### 三条功能诉求

1. **能起奇门局** —— 转盘 / 九宫局盘 / 罗盘,主位在镜头内
2. **能开播** —— 手机支架 · 环形补光灯 · 手写招牌(字很丑)· 入镜的背景
3. **能藏东西** —— 折线图 · 抄满弹幕的本子 · 洗干净的第一只奶茶空杯 · 半夜练字的纸,全在镜头外那半

### 与阿云房的分野(避免两间屋子同质)

| | 阿云房 | 桃桃房 |
|---|---|---|
| 气质 | **放着不管** | **收得整整齐齐但不敢拿出来** |
| 唯一擦拭的 | 式盘桌(对外那件) | 镜头内的一切 |
| 乱的地方 | 到处 | 没有乱的地方 —— 藏的地方也是整齐的 |
| 光 | 暖 · 烛火 · 昏 | 冷白补光(右)↔ 暖黄台灯(左),**两种光源就是两个人格** |

**两种色温是这间房最省力也最有效的表达**,`grade` 做不到就用局部光源。

## 定案:摇摇床(2026-07-20 · 用户判读)

代码注释写的是「兔窝(草窝 + 菜叶)」,但**实际绘制**是一个椭圆吊篮 + 一圈放射麦秆(`pxE` 三层 + 10 根秆),兔子元素只有旁边两片绿菜叶。用户看渲染判读为**摇摇床**,并给出用途:**桃桃会去玩**。

按此定案,并**合并掉另一件**:原「吊篮椅(右中·从梁垂)」在现状里只画了一个桃子坐垫,秋千本体在动画层 —— 它与摇摇床职能重复(都是吊着晃的玩物),合为一件。

**为什么这件比兔窝好**:兔子在档案里没有出处,摇摇床有 —— 二十二岁、网红、需要一个「不表演的时候待着」的地方。

**它是这间房第二件横跨分界线的家具**(第一件是奇门局桌):

| 时段 | 身份 |
|---|---|
| 开播时 | 入镜道具,网红标配,她坐上去晃两下给镜头看 |
| 下播后 | 瘫在上面刷自己的回放,数弹幕 —— 这半边没人看 |

**S3 要给它一个 act**:桃桃走过去、躺上、慢晃、看手机。晃动幅度要极轻(参考海报飘动的克制)。

### 修订后校验

| 项 | 结果 |
|---|---|
| 重叠 / 越界 | ✓ 无 |
| 连通性 | ✓ 947/947 全可达 |
| 左右配比 | 363,400 : 389,600 = **0.93**(合并一件后更平衡) |

## 现状诊断(2026-07-20 · 对照定稿档案)

### 结论:房间画的是另一个角色

现状把「少女感」当主线,长出了一整套**古典才女**符号,与档案里的人对不上。

| 现状物件 | 它说的是谁 | 档案里的桃桃 |
|---|---|---|
| 古琴桌 + 古琴 | 抚琴的闺秀 | 昼伏夜出,晚八点开播 |
| 围棋小桌 | 对弈的雅士 | 骂人一句到底,句尾带「哼」 |
| 绣绷(绣一半的桃花)+ 线笸箩 | 刺绣的姑娘 | 改良道袍配运动鞋,耳机挂脖子 |
| 胭脂水粉排 + 首饰盒 | 描眉的小姐 | 不会用表格软件,又不肯问人 |
| 团扇 ×2 · 纸伞 | 古典布景 | 凌晨的伙食,泡面级别 |

**这六件要撤**。不是因为画得不好,是因为它们属于另一个人。

### 站得住的(保留)

- **奇门**:局桌 · 罗盘 · 令旗筒 · 八卦镜 · 洛书轴 —— 专业线完整
- **桃花岛**:桃木剑(墙横挂 · 红穗)· 桃花屏风 · 桃枝 —— 来处清楚
- **网红**:直播角(环形灯 + 手机)· 应援灯牌「桃」· 拍立得照片串 —— 现代兴趣落地了
- **练功桩(缠红布)** —— 真功夫,不表演,正是「镜头外」那半该有的

### 缺的(档案核心,现状一件都没有)

「镜头外那半」的**全部证据**目前是空的:

1. **手画的准确率折线图** —— 贴一面墙。她的要强、她的不肯问人,全在这上面
2. **洗干净的第一只奶茶空杯** —— 九块九那笔打赏。后面陆续摆成一排
3. **抄满观众 ID 与弹幕的本子** —— 「关我什么事」然后抄下来
4. **半夜练字的废纸** —— 揉了扔,纸篓满的。对照她那块字很丑的招牌
5. **师父的香位** —— 嘴上说来还愿,其实是道歉

### 其余三个结构问题

- **没有分界线**:少女感均匀铺满全屋,镜头内/外没有分野。屏风现在只是右下角的装饰,应升格为这条线本身
- **凑密度的痕迹**:「加密道具层 +28 件」「加密 v2」这种命名本身就是症状 —— 物件是**加**上去的,不是**长**出来的。花瓣散落 14 处同理
- **字丑的梗没落地**:档案给了「招牌字很丑 + 半夜偷偷练」这个反差,现状有洛书轴却没有那块丑招牌,对比不成立

### S3 施工顺序(据此修订)

1. 撤六件古典才女符号 + 花瓣散点
2. 屏风升格为分界线(有状态)
3. 补五件「证据」到左半
4. 梳妆台并入直播台
5. 双色温:冷白(右)/ 暖黄(左)

## 桃桃睡姿(并入 NPC 拆解那一轮)

要求:**垂直睡 · 睡在床中央 · 枕头放好**。阿云那一轮踩过的坑已写进 B0 规范与 METHOD T6,这里直接照规范做,不重新试错。

### 硬规则(来自阿云睡姿的返工)

1. **头部逐字复用 `stand` / `standside` 的头,不许另画**
   阿云那次我手绘了一个头,用户原话「人脸还是完全可以沿用已经有的角色设计来吧，现在都不像了」。复用是唯一解。

2. **被子的宽度要配合头部轴心,不是反过来**
   阿云的头占 2–11 列(轴 6.5),我按 0–11 画被子(轴 5.5),结果脖子是歪的。用户给的解法更好:「你可以把被子图宽 1px 之类的来配合头部」→ sprite 加宽到 13 列。**桃桃同理:先定头的轴,再定被子宽度。**

3. **不许走进床里再睡**
   用户原话「睡觉不用先走进床内部，到床边就可以跳到睡姿了」。做法:寻路锚点放在床的**下沿之外**,到位后切 `sleepAt` 坐标,直接落到床中央。

4. **睡在床正中**
   `sleepAt` 由床心减去 sprite 半宽算出,不写死数字 —— 参照阿云 `sleepAt: [1208, 508]` 的算法(床心 1260 − sprite 宽 104/2)。

5. **枕头要在头下**
   桃桃的床是幔帐床,现状枕头位置需实测。阿云那次枕头原本是「纯色矩形加两条线、只占床宽 27% 缩在左角」,重画成七层并横跨床头居中。桃桃的枕头按同一标准做,并确保**头正好落在枕头上**,不是压在枕头旁边。

6. **`zzz` 气泡 + 呼吸动画**,与阿云一致(两帧交替,`fps` 极低)。

### 桃桃特有的新问题

- **长发**:垂直睡姿下头发要铺开在枕头上,这是阿云(道髻)没有的情况。铺开的头发会让 sprite 比阿云的 13 列更宽,**被子宽度要跟着头发的实际占宽走**,不是跟着脸走
- **帐幔**:阿云房的帐幔已按用户要求删除;桃桃的幔帐床是否保留帐幔,取决于后续风格评审 —— 睡姿设计不要依赖帐幔遮挡来藏破绽

### 验收

`poseshot.js` 出图目视 + 确认三点:头不歪、人在床正中、头落在枕头上。

**屏风的状态挂在 `live` 行为上**：`roomState(TAO_ROOM, { streaming: st.act.id === 'live' })`。状态放在房间而不是屏风内部，所以台词、色温这些别处也读得到 —— 这是 `roomState` 注释里写明的要求。

**镜头朝向的判读**（此前差点搞错）：镜头架在左侧朝右拍，背景是月洞窗。所以环形灯、自拍杆、梳妆台在左侧**是对的** —— 它们是拍摄位，不入镜。左下角才是「镜头绝对拍不到」的地方，五件证据全在那里。

一度按「左证据 / 右舞台」的抽象规则判定设备放错半边、准备重排 69 件家具，是用户一句「这是 taotao 的房子，不是我的」拦下的。**按角色的逻辑推，不要按自己发明的规则套。**

# 村民屋 · 生产协议

**开一间房,从这里开始,照着走完。** 这不是经验总结,是**协议** —— 每一步写死:查什么 → 怎么查(命令) → **有就怎么优化 / 没有就怎么设计** → 过什么门 → 产出什么。

前四间(阿云/桃桃/婆婆/丹增)是把引擎「用」出来的过程,协议是从那四间的返工里反推的。跳步的代价都实测过:跳 S3 直接画换来 137 个 commit 全线回退;跳 S10 只验一段脚本,缺逗号一路通过;门禁工具写死房间清单,丹增房**整间从未被 verify 看过**却天天报「全部通过」。

> 本文 = 怎么走 · `ENGINE.md` = 引擎能什么怎么调 · `PLAYBOOK.md` = 事故模式 · `METHOD.md` = 单间设计手法 · `ENGINE-GAPS.md` = 尚未收编的缺口

```
S1 角色检查 ★门禁 → S2 立项 → S3 平面 → S4 骨架 → S5 素材 → S6 姿态
              → S7 行为 → S8 交互叙事 → S9 验收 → S10 沉淀
                                            (S0 准备只做一次)
```

**先有人,后有房。** 房间是人的外化 —— 所以第一步不是「写档案」而是**检查这个人够不够开房**(`castlint`),不够就补到够,补不出来**不开工**。S1 含糊,后面每一步都是编的。

---

## 每一步都是【细致检查】· 认三种状态 ★ 读表方式

每步的表格按这个形状读 —— 检查不是「有没有」,是**三档**:

| 状态 | 意思 | 协议给什么 |
|---|---|---|
| **合格** | 达到判据 | 说清**往下一步传什么** |
| **写了但没写好** ← 最常见,最容易漏 | 写了,但薄 / 泛 / 撞车 / 落不了地 | **判据**(什么算写好了)+ **怎么补强** |
| **没写** | 空的 | **从哪推导出来**,依据什么,不许自己编 |

> 「写了但没写好」这一档是大多数返工的来源:桃桃房那套古典才女陈设不是没写档案,是档案写得不够利;丹增侧背走不是没有姿态,是姿态**名字**齐而**像素**是同一帧。
> **只判「有/无」的检查,一定会把这一档放过去。**

机器判不了的项,**列成待确认清单让人逐条回答**,绝不假装能判 —— 那是第五种假绿(前四种见 `PLAYBOOK` 事故模式 14 / 20 / 21)。

### 假绿第六种:门禁要求的工具【不存在】★ 2026-07-22 实测

S7 从第一版就写着「`pathlint` **0 处**」,连实测数字都在正文里(桃桃 14 处穿模、阿云 4 处),
但 `tools/` 里**根本没有这个文件** —— 它随那次 137 commit 回退一起没了,和 WALKROUTE 同一批。
**要求跑一支跑不了的工具,等于这一关谁都过。**

重建后立刻抓到 3 处真错,全在**已经验收过的四房里**:婆婆睡觉停在床外 118px、
阿云打水和猫喝水的锚点都被风箱堵死。那是门禁空写期间攒下的债。

> **协议**:每条门禁写下时,`ls tools/` 确认那个文件在。文档里出现的工具名,
> 要么有文件,要么明写「**待建**」并计入欠账 —— 不许让一个不存在的工具替你把关。

### 假绿第七种:工具参数传错,静默空跑 ★ 同日实测

`roomaudit` 的第二个参数是**模块名**(`A`/`B`/`C`/`D`),不是房间名。
我一路传 `roomaudit.js <file> shenyan`,于是内部 `show(m) = !ONLY || ONLY === m` 对所有模块都 false ——
**什么都没打印,什么都没计数**,末尾照常打出「✓ 四模块全过」。整个 S5 阶段我都在看这句假绿。

传对参数重跑,B 模块当场报:沈砚房表演时**画面没有任何变化**。

> **协议**:工具跑出来**一个细节都没有**却报绿 —— 那不是「干净」,那是**没跑**。
> 判据:绿色结论旁边必须有**它查了什么的证据**(件数 / 条数 / 覆盖率)。
> 只有一行「全过」而没有任何计数的输出,一律当没跑,回去看用法。

## 检查之间有【依赖】★ 前置没过,后面的绿是假的

这是顺序不能乱的真正原因 —— 不是流程洁癖,是**前置错了会让后面的检查失去意义,而它们照样报绿**:

```
立意(S2)  ──→ 布局取舍 · 做旧 · 光 · 台词      立意漂了,后面每个视觉决策都失去对照
   │
foot(S5)  ──→ roomGrid 烧格 ──→ gridPath 寻路 ──→ pathlint 锚点/路径
                                                  ↑ foot 画错,pathlint 报 0 是假的
draw 出像素(S5) ──→ 布局重叠/通道 · 逐件命中     素材画不出,这些检查全在空转
   │
姿态存在(S6) ──→ 行为演得出(S7) ──→ 表演态(S8)   姿态回退 stand,行为表看着对但演不出
   │
stateKey(S8) ──→ 道具 fx/light 读状态 ──→ 表演有视觉
                                          ↑ 没 stateKey,人走到了也等于没发生
sortKey/attach(S5) ──→ 命中排序 ──→ 点得到的是不是它自己
```

**五条最容易踩的**:

| 依赖 | 前置错了会怎样 | 后果 |
|---|---|---|
| `foot` → 烧格 → 寻路 | `pathlint` 照样 0 处 | 角色走进家具里,而门禁全绿 |
| `draw` 出像素 → 一切 | 素材静默不画(异常被吞) | 看着像层序问题,方向全歪 |
| 姿态存在 → 行为 | 姿态名写错**静默回退 stand** | 「他在读书」实际站着发呆 |
| `stateKey` → 道具响应 | 表演跑完但画面不变 | 玩家判定「按钮没用」,而她每次都走到了 |
| 立意 → 视觉决策 | 每件单看都合理 | 整间房不知道在说什么 |

**所以**:每步的检查表都标了**依赖**。前置那步没绿就往下走,拿到的绿**不作数** —— 回去。

## 四条铁律(贯穿全程,违反即回炉)

| | |
|---|---|
| **先引入,再新建** ★★ | 任何「我需要一个 X」的时刻,**先穷尽 X 是不是已经有了**。见下方判据 |
| **空不是缺陷** | 完成 = 身份契合 + 功能成立 + 布局合理,**不是填满**。数量指标是参考不是目标,为凑数拆件一律驳回 |
| **不许复用布局骨架** | 每间房的拓扑必须自己长。撞车就回炉 —— 36 间同一套骨架换皮 = 36 间都不成立 |
| **未验收的手法禁止批量推进** | 第一间做完**停下交付**,确认手法再推广。这条是 137 commit 返工换来的 |

### 铁律一 · 先引入,再新建 —— 判据与反射(2026-07-22 补,用户三次指出才落地)

**「grep 了一次没找到」不等于「不存在」。** 穷尽的标准是这三问,三问都答「没有」才允许动手画:

| 问 | 沈砚正面这次的答案 |
|---|---|
| ① 系统里**已经在显示**这个东西的地方在哪? | 图鉴卡每天在渲染四十个角色的正面 —— 那条渲染路径(`codexGrid` 读 CSS 精灵)就是数据源。我没问这一句 |
| ② 别处**做过同一件事**的实现在哪? | 前四房的宠物全是 actor + 行为表 + 寻路。我却给猫发明了 variant 换帧,做出三只钉在原地的猫 |
| ③ 已有的**工具/门禁**是不是已经在查它? | `posegrid` 的轮廓检查是我自己加的,却没想到拿它反查四房 |

**最坏的一环是「画完之后给它找理由」。** 发现 CSS 精灵之后,我用「它是头像不是行走图」保住了已经画好的东西 ——
那个理由是**画完才想出来的**,它让错误看起来像判断。规范画的就是这个角色,尺寸不合该迁就规范,不是反过来。

**为什么会反射性地画而不是找**:画出来立刻有东西可看可提交;找现成的要读别人的代码、理解数据结构、
而且**可能发现自己刚做的白费**。后者没有即时反馈 —— 所以要靠铁律顶着,不能靠自觉。

### 铁律一之二 · 规范对房间是【只读】的 ★★(同日,第二次翻车换来的)

发现「规范缺了」之后,我的下一步是**往规范里写**(把四间房自画的正面搬进 `FRONT_OVR`)。
方向看着对了 —— 单一数据源、改一处 —— 但那仍然越权:**我把房间的产物提升成了基准**。
基准该由设计侧定,不能由消费它的房间反向写入。用户要求恢复,已 revert。

| 房间对规范可以做什么 | 不可以做什么 |
|---|---|
| **读**、引入(`codex:` 字段)、照它画 | 往 `FRONT_OVR`/`SIDE_OVR`/`BACK_OVR`/`WALK_OVR` **写入新角色或新朝向** |
| 发现缺口 → **报告 + 给出数据**(缺哪几个、差多少格) | 自己补上,哪怕内容是现成的 |
| 发现错误 → **做检查工具把它固化成账**(如 `symlint`) | 自己改正,哪怕改法很明显 |

**判据**:任何一次 `design.html` 的改动,如果 diff 落在 `var *_OVR={` 这几张表里,
停下来问一句「这是设计侧该拍的板吗」。答是 → 报告,不动手。
本轮唯一动过规范的一次(沈砚背面居中)是**用户先看过方案、明确说「你处理完我看看」之后**才做的。

**环境**:`export PATH="$HOME/.bun/bin:$PATH"`,工具一律传**绝对路径**,`regress` 必须**从仓库根**跑,参数**文件在前模式在后**(写反 → `ERR_INVALID_URL`,看着像工具坏了)。

## S1 角色检查 —— 够不够开房 ★★ 门禁,不过不许进 S2

**起手第一件事:`bun tools/castlint.js <file> <角色id>`。**

房间是人的外化 —— 分界线、三条功能诉求、每一件物、每一句台词、`sayDeep` 那句真话,**全是从档案推出来的**。档案薄,后面每一步都是编的:桃桃房曾长成一整套古典才女陈设,撤了九件,根因就是开工时没把人写清。

`castlint` 把检查分成**机器判死的**和**机器判不了的**两类,后者列成待确认清单 —— 不假装能判「设定够不够丰富」,那会变成又一种假绿。

### ① 总表 B9 十字段 —— `castlint` ① 段

ID / 名·号 / 流派 / 出身 / 性格 / **缺一个字** / 背景 / 关键经历 / 说话风格

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 十字段非空,**且每一项都能回推到「缺一个字」** —— 它是全部行为的解释项。往下传:S2 的立意直接由「缺 + 失败方式」写出 |
| **写了没写好** | 症状:字段填了但**互相不咬合**(性格与「缺」无关、关键经历没落在「缺」上)。判据:遮住「缺」那一栏,光看其余九项能不能猜出缺的是哪个字 —— 猜不出就是没咬合。补强:以「缺」为轴逐条重读,不咬合的改掉,**别加新字段** |
| **没写** | 从 B9/B10 补,**不得自立设定** —— 我给桃桃编过「缺服气」,而 B9 白纸黑字写着「缺直率」,原设好得多。补不出来**停下问用户**,不自己编 |

### ② 画得出来吗 —— `castlint` ② 段

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | codex 四向齐 + 走路帧二齐 → `defineActor(id,{codex:id})` 直接用 |
| **部分有**(最常见) | **FRONT 缺** → 房间自画正面姿态(`codexPoses` 只覆盖移动姿态,站姿本来就留给房间);**帧二缺** → 补 `WALK_OVR`:拿 SIDE/BACK 帧一,躯干原样、**末行两块腿合并居中**(帧一分立=着地 ↔ 帧二并拢=摆动)。不补就**必然滑行** |
| **看着有其实没有** ★ | 姿态**名字**齐而**像素**是同一帧 —— `poselint` 会说「全符合 B0」。`castlint`/`walklint` 比像素。房间 loop 里**不许**写 `walkside2 = walkside1` 这类兜底,它会覆盖 codex 真帧还骗过门禁 |
| **全无** | 该角色不在 codex —— 四向全要新画,是独立美术工程,**先评估再开房**,别边做房边画人 |

### ③ 撞不撞车 —— `castlint` ③ 段(对照 `cast-registry.json`)

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 失败方式 · 分界线形态 · 兴趣 · 屋子气质 **四个维度都不与已开的房重复** |
| **撞了** | 换一种,别硬凑近似的。**失败方式重复 = 角色重复的根源**;分界线形态的替换见 S2 |
| **查不了** | 登记表没回填过 —— 先把已开房的四维度补进 `cast-registry.json`,否则这项检查等于没做 |

### ④ 档案深度 —— `castlint` ④ 段八条,**机器判不了,逐条答**

来处给的一句话 / 证明过自己的那次 / 失败的方式 / **兴趣能落成哪些物件** / 分界线的物理形态 / 笑点即痛点 / 一道裂缝(`sayDeep`) / 反差落在同一个伤口上

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 八条都答得出,**且兴趣那条列得出具体物件名**(不是「喜欢摇滚」,是「鼓组·电吉他·音箱·鼓槌」),**并且这些物件够撑起房间的一块区域** —— 四房实测:桃桃的直播区占半间房、丹增的鼓组占整个右侧、阿云的二次元角、婆婆的毛线贯穿全屋。**反差爱好是房间的一极,不是几件小物点缀** |
| **写了没写好** ← 返工重灾区 | 症状:答了,但泛。判据四条 ——(a)**兴趣落不成物件** = 房间无从画起;(a2)**兴趣只落成几件小物** = 反差不够分量,放大到能占一整侧(沈砚从「买彩票」放大成「用梅花易数推彩票号码」,于是有了推号墙+推号桌+开奖角);(b)**分界线是概念不是东西**(「新与旧的对比」不算,「蒙尘↔锃亮」才算);(c)**裂缝说的是反面而非同一件事**(「被逼着才说」本身就是那个缺的形状)。补强:回 B9 的背景/关键经历里找具体的物,别在抽象层打转 |
| **没写** | 从 B9 的背景 + 关键经历推。**「没有那句话」本身可以是答案** —— 婆婆没有师门,没人给过她那句话,那正是她的缺 |

**几条要点**(每条都是返工换来的):
- **「没有那句话」本身可以是答案** —— 婆婆没有师门,没人给过她那句话,那正是她的缺
- **兴趣必须能落成物件** —— 列不出具体物件名,房间就无从画起
- **一道裂缝**:核心物件追问三次他松口。**「被逼着才说」本身就是那个缺的形状**,不是它的反面
- **反差落在同一个伤口上** —— 桃桃骂观众笨蛋却记得每个常驻 ID,因为她最知道被忘记是什么滋味。反差不是另加的性格,是同一件事的背面
- **四人的缺是咬合的** —— 谁能填谁的缺决定了谁和谁走得近,关系网不用另行设计,它自己会长出来

**门禁**:`castlint` ①② 全绿(机器可判部分)**且** ④ 八条逐条答得出。**两者缺一不许进 S2** —— 只过 ①② 就开工,做到 S8 会发现这间房没有要说的话。

**开完房记得回填 `cast-registry.json`** —— 把这个角色用掉的失败方式/分界线形态/兴趣/屋子气质登记进去,下一间才查得到重复。

## S2 立项 —— 房间要说明他的什么 ★ 门禁

**产出**:`ROOM-<id>-S1.md`。**没写就复制模板** `templates/ROOM-S1.md` 照着填 —— 模板每节自带判据。
**查**:`bun tools/roomlint.js .roomwork/ROOM-<id>-S1.md`(查结构、占位残留、分界线撞车)。

### ① 一句话立意

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 这句话能拆成「**缺一个字**」+「**失败的方式**」两半。往下传:S3 之后每个决策都拿它对照 |
| **写了没写好** | 症状:是**描述**不是立意(「一间摇滚僧人的屋子」)。判据:**遮住角色名还认得出是谁吗** —— 认不出就是太泛。补强:把 S1 ④ 的「失败的方式」塞进这句话,泛的通常就是漏了它 |
| **没写** | 写不出 = S1 没做够,**回 S1**,别在这里硬憋 |

### ② 分界线的物理形态 ★ 全房最关键的一条

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 三条全中:**(a)** 是东西不是概念 **(b)** 不与已用的重复 **(c)** 玩家扫一眼全屋就读得出。文档里写成 `**形态**: <名词短语>` 那一行,`roomlint` 才查得了重 |
| **写了没写好** | 症状一:**概念不是东西** ——「新与旧的对比」不算,「蒙尘↔锃亮」才算(前者画不出来,后者是 16 件法器上的浮尘)。症状二:**换皮** —— 名字不同但机制同(「上层下层」就是「左右两半」转 90°)。补强:问自己「这条线由**哪几件物**承载」,列不出物就是概念 |
| **没写 / 已用完** | 已用四种:①一件 vs 全屋(阿云)②左右两半·空间切分(桃桃)③成对物件同框(婆婆)④保养状态·蒙尘↔锃亮(丹增)。**一律不许再用**。再想一种,从他的「失败方式」找:那个失败在物理世界留下什么痕迹 |

### ③ 三条功能诉求 ＋ 起居 ★ 两样都要,漏一样房间就不完整

**功能诉求**是他的「活」(职业 · 爱好),**起居**是他的「日子」(睡 · 吃 · 喝 · 洗)。
协议原先只问前者,于是沈砚房画到 30 件才发现:**他住在这儿,却没有床、没有碗、没有一口热水**。
四房不缺这块,是因为它们从旧房迁移时本来就有 —— 新房从零起,不写就真的没有。

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 三条功能各自**跟着一串具体物件名**(「选日子 —— 藏历经桌·历书·骰卦盘」);**外加起居四问都答得出**:睡在哪 · 吃什么 · 喝什么 · 洗漱在哪(用不上的可以明说「他不在这儿睡」,但要说) |
| **写了没写好** | 症状一:功能写成抽象动词(「修行」「思考」)—— **列不出物件名 = 这条画不出来**。症状二:**起居当背景板** —— 摆张床就算完。判据:**起居同样要能回推档案**,它是最省力的角色刻画:沈砚拿一摞书当枕头、粥就咸菜;阿云的床是「一件 vs 全屋」那一件;桃桃的收得整整齐齐 |
| **没写** | 功能从「兴趣 + 缺」反推;起居从「他有多少钱、跟谁住、什么时候睡」反推 —— 清贫的人不会有第二把椅子 |

## S5 素材 —— 先查库,缺什么才画

**库存**:265 件(`generic` 130 可跨房复用 / `character` 136 专属)。

### ① 默认是【自己画】—— 复用只限不承载身份的小物 ★★

**四间做到线的房实测:阿云 / 桃桃 / 丹增素材自画率 100%,婆婆 91%** ——
她借的那 7 件是挂钩、扫帚、坐垫、板条箱这类。**这就是标准,不是意外。**

家具是**角色的外化**。沈砚的书桌和阿云的书桌不该是同一张:
一个是七次落榜的人趴着的桌子,一个是懒道士堆着零食的桌子。
借一张过来,这间房就说不出自己的话了 —— 而 36 间房各借几件,
最后是 36 间**长得一样**的房。

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 承载身份的件**全部自画**;复用的只有「任何屋子都有、且长得都差不多」的小物 |
| **判据** ★ | 逐件问:**遮住其余部分,单看这一件,能读出是谁的屋子吗?**<br>能 → **必须自画**(桌案 · 收纳 · 职业用具 · 床卧 · 墙面主件 · 光源);<br>不能 → 可以借(扫帚 · 挂钩 · 蜡烛 · 碗碟 · 蛛网 · 门垫 · 板条箱) |
| **写了没写好** | 症状:借了大件,房间看着像另一间房的碎片。**自画率低于 85% 就要回头看** —— 是不是把该说话的件借了 |
| **反向的错** | 同一件小物库里已有又新画一个近似的 → 两份维护、风格漂。`grep 'def("' design.html` 搜同类词 |

> **成本不在这里省。** 一间房五六十件素材,自画是本分;要省成本得从
> **立意清楚**(不画用不上的件)和**手法复用**(`METHOD.md` 的分层/剪影/做旧手法跨房通用)来省,
> 不是从借家具来省。

## S6 姿态 —— 这个角色能不能走 ★ 批量生产的头号阻塞

### ① 四向与走路帧二

|---|---|

| **三支全绿却是错的** ★ | 沈砚第一版:头部多占一行、躯干宽一格、两脚间距也不同 —— **同一个人转个身胖一圈**。`poselint`(名字)、`walklint`(像素)、`roomaudit A`(引用)三支都看不见这件事,是用户看图看出来的。补强:拿规范给的 `standback` 当基准逐行对齐,头部占几行、肩线在第几行、腰带在第几行、两脚间隔几格,全部照抄 |
| **参照别取错** | 要比的是**这个角色实际在用的背面**(`poses.standback`),不是规范里那张 —— 阿云和桃桃根本没声明 `codex`,背面是房间另画的一套,拿规范去比是比错了对象 |
| **行数不等未必是错** | 婆婆的正面图本来就骑着扫帚(顶上五行是刷毛和杆),比背面高 5 行是对的。工具把「行数不等」降级成提示,只有**行数相同而逐行宽度不同**才判错 |

另一条同源的:**眼睛那一行不要画鬓发**。`E`(眼)紧挨着 `H`(发)在 8px 一格下会连成一片,
脸上就只剩一张嘴。规范里有正面图的角色(雷鸣 `.KFEFFFEFFK.`)眼行都不带 `H`。

### ⑥ 剪影 —— `posegrid`,**用眼睛**

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 摊开姿态表,遮住名字也认得出每个在干什么 |
| **三支全绿却仍然错** ★ | 沈砚第一版:名字齐(`poselint` ✓)、像素各不相同(`walklint` ✓)、无幽灵引用(`roomaudit A` ✓),但 `sit`/`read`/`write` 的**轮廓和 `stand` 一样** —— 402px 的屏上他只是站着。**姿态是靠剪影读的,不是靠里面的像素**。补强:跪坐矮三格且下摆铺满、捧的书探出身体轮廓、前倾改用侧影(正面画不出前倾) |

## S7 行为 —— 他在房里干什么

`ACTS` 行为表 → 状态机调用引擎。**依赖 S5 的 `foot`(锚点校验才作数)和 S6 的姿态(行为才演得出)**。

### ① 调度一律调引擎

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | `pickAct` · `startWalkTo` · `stepWalk` · `walkPose` · `stepPace` · `idlePose` · `stepFly` · `stepPursuit`,房间只留自己特有的筛选条件 |
| **写了没写好** | 症状:房间自写 BFS / 自写选行为 / 自写站姿微动 —— 同一职能两套实现,**两份就会漂**(路网的边由人手连,每加一件家具都可能悄悄让某条边失效,症状是「角色偶尔从柜子上走过去」) |
| **没写** | 房间脚本只做三件事:**声明数据、推进状态机、调用引擎** |

### ② 行为表的语义

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 权重 `w` 体现主次(主播的主业是直播,不该和逗兔子同概率)· 按钮驱动的行为标 `exclude:true` · 字段名与引擎读的一致 |
| **写了没写好** | 症状一:**忘标 `exclude`** → 按钮行为被随机选中,并按它的 `dur` 把人钉在那儿。症状二:**字段名对不上** —— 婆婆的起飞行为标 `flyMode` 而渲染读的是 `fly`,于是飞到位就落地了。判据:grep 行为字段名 vs loop 里读的名字 |
| **没写** | 从 S2 的三条功能诉求推 —— 每条功能至少一个行为 |

### ③ 锚点 —— `pathlint` **0 处**

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 锚点不在家具内、路径不穿家具。主角锚点 = sprite 左上角;宠物**本身就是脚点**(`startWalkTo` 传 `{foot:[0,0]}`) |
| **写了没写好** | 症状:**挪了家具没挪锚点** —— 食盆换了位置,「站在哪儿喂」还留在原处,于是她站到盆里。**家具和它的行为锚点是一件事,不是两件**。改坐标必跑 `pathlint` |
| **不作数** ★ | `foot`(S5)没查过就跑 `pathlint`,报 0 也是**假的** —— 碰撞体错了,穿模照样过 |

**判据是什么,更要紧的是判据【不是】什么** —— 重建 `pathlint` 时连错两版:

| 看着像错,其实是对的 | 为什么 |
|---|---|
| 锚点落在家具的碰撞格里 | `startWalkTo` **无条件**把锚点 push 到路径末尾,`gridPath` 的 `near()` 退到最近可达格 —— 走到桌边坐下、走到床边躺下,锚点本来就在家具的 `NAV_PAD`(16px)膨胀区里。**把这个当穿模,四房会报 34 处** |
| 从最底一排泛洪判可达 | 起点落在 `room.extBand`(门外那截),与房内不连通 —— 阿云房 18 个锚点报了 17 个不可达 |

**真判据只有两条**:① 脚点落在家具 `foot` **本体**内(不含 PAD)= 他站在柜子里;
② **问引擎走一趟**,看 `gridPath` 实际把他放在离锚点多远 —— 超过两格(80px)就是够不着。
不要自己造可达性判据,引擎怎么走的,就按它怎么量。

**行为表要挂在房间对象上**(`ROOM.acts`)`pathlint` 才查得了 —— 它和 `plan` / `perform` 一样是房间数据。
挂载点必须在 **loop 的首帧接线处**(与 `wirePerform` 并列):挂在 `startWalk` 定义处会撞 TDZ ——
阿云的 ROOM 对象在**另一个 script 块**、桃桃的 `RACTS`、婆婆的 `PETS` 都在那一行之后才 `const` 初始化,
整个房间脚本当场抛错,而页面只是静静地少了交互,什么都不报。

### ④ 表演时的行动 —— `roomaudit B`

| 状态 | 判据 / 怎么办 |
|---|---|
| **合格** | 玩家点了按钮,他**赶路的速度快于平时闲逛** |
| **写了没写好** | 症状:`stepWalk` 速度是**固定值**,表演和闲逛一个速度 —— 玩家点完要等他慢慢晃过去。判据:`roomaudit B` 查速度参数有没有条件分支。**当前四间房全是固定值,没有一间实现了表演加速** |
| **没写** | 表演是玩家**唯一**发起的动作,让他磨蹭是最直接的挫败感 |

**门禁**:`pathlint` **0 处**(且 S5 的 `foot` 已验)· `roomaudit B`。

## 这间房要说明他的什么

> **他被赶下山去找「静」，找到了 —— 却是寺里不会承认的方式。**

寺里让他「练完一百零八式再回来」找静。他找到了：**打鼓的时候心是静的**。但那不是坐禅的静，是摇滚的静。所以他不敢回去说，也不再礼佛 —— 一百零八式停在最后几式，不练了。

## 分界线的物理形态 ★ 本案关键决策（第四种）

前三房的分界线：阿云「一件 vs 全屋」、桃桃「左右两半（空间）」、婆婆「成对物件同框」。丹增要第四种，**不重复空间切分、不重复成对**。

**形态**:保养状态的对比 —— 蒙尘 ↔ 锃亮

丹增的分界线是 **保养状态的对比 —— 蒙尘 ↔ 锃亮**：

| 蒙尘的一半（他不信了） | 锃亮的一半（真让他静的） |
|---|---|
| 佛龛落灰、酥油灯干了 | 摇滚鼓组天天擦，铜片反光 |
| 经卷卷边、唐卡褪色 | 电吉他上没有一点灰 |
| 供桌上的法器蒙尘 | 鼓槌磨得发亮 |
| 坛城沙画积了浮尘 | 音箱擦得锃亮 |

**不是空间左右分**，而是**同一屋里，东西按「有没有人擦」分成两个世界**。经堂那半是他被要求信的过去，鼓那半是他真正珍视的现在。玩家扫过全屋，从灰尘的厚薄就读出他心在哪边。

**核心物件 = 一百零八式的记数牌**，停在某个数字很久没动。它跨在分界线上：**停着不动（像经堂被搁置），但没落灰（他天天看）**。点它 → 他不说练到第几式；追问三次 → 「差最后几式。我知道怎么练完。就是练完了……得回去说」。

## 三条功能诉求

1. **打鼓** —— 摇滚鼓组 · 电吉他 · 音箱 · 鼓槌。他真正的「修行」，天天擦
2. **选日子** —— 藏历密算，替人断吉日（红白喜事都找他）。算日子不算人
3. **（积灰的）礼佛** —— 佛龛 · 酥油灯 · 经卷 · 坛城 · 一百零八式记数牌。功能还在，只是不再用

### 账目终结（2026-07-21 · autorun 续）

上一轮记的「姿态复用帧一（视觉即帧一）」其实是**滑行 bug**，不是达标——侧/背走复用帧一 = 腿不动、整个人平移。根因深挖：

- codex 的 `codexPoses` 把 SIDE 帧一同时赋给 `walkside1` 与 `walkside3`，帧二 `walkside2/walkback2` **只有 `CODEX.WALK[id]` 提供时才有**。`WALK_OVR` 全表只有 6 个角色（popo/xuanming/bailu/suhe/xueyao）有走路帧二，**tenz 不在其中** —— 规范根本没画他的侧/背迈步帧。房间 loop 的首帧补齐段又把 `walkside2=walkside1` 复用回帧一，坐实滑行。
- 正统修复（单一数据源）：给 `WALK_OVR` 补 `tenz.side` / `tenz.back` 迈步帧二（基于 SIDE/BACK 帧一躯干、改腿部作开合），删掉房间里复用帧一的覆盖，loop 走姿改 `[walkside1,walkside2,walkside3,walkside2]` 站-迈-站-迈、背走 `walkback1↔walkback2` 交替。
- 复核四主角：`ayun/tao/popo/tenz` 走姿全部 verified **无滑行**。阿云/桃桃帧二是各自房间自画、婆婆在 WALK_OVR 里，只有丹增因迁移方式漏了 —— 是丹增独有，非四房共性。

**plan 60 vs 65-85 —— 按 `room-completion-standard` 铁律终结,不硬凑。** 逐个复数合并件复核：`snow_lions`（一对护法已同框守佛龛+立意台词，拆开破坏成对完整感、台词还得拆重）、`vajra_knots`/`gau_boxes`/`seven_bowls`（一串结/一叠盒/七供本就是整组物件）——拆开均为凑数或有损，无一有叙事增益。60 是丹增房（经堂+鼓+武术三区）的合理落点，非质量缺陷。

### 蒙尘质感 —— 撤回「不做」，已做（2026-07-21 · autorun 续）

上面记的「经堂降饱和判断不做（改 30 素材 draw 风险大、效果不确定）」是**站不住的 defer**：蒙尘↔锃亮是丹增房**分界线立意本身**（S1 第四种），不是可选 polish；而「改 30 素材 draw」是**错的攻击面**（水泥层硬改颜色，当然又脏又险）。

正确做法在**引擎层**：`makePatina(src)`，`placeAsset` 见 `opt.patina || a.patina` 就把 sprite 换成做旧版，缓存一次。**不用 `g.filter`**（小程序 canvas 不保证支持 CSS 滤镜）。**泛用引擎能力**（任何「没人打理」的一侧都能用），房间只在素材上标 `patina: true`。

标了 16 件「他不再礼佛」的经堂法器（altar/thangka/offering_table/prayer_wheels/torma/dharma_wheel/mani_stones/dungchen/seven_bowls/butter_flower/gau_boxes/vajra_knots/snow_lions/khata_rod/hand_wheel/sutra_shelf）+ 坛城 mandala（沙画积浮尘，用时金光在 fx 层醒来）。**不标**还在用的（选日子的经桌 sutra_desk、还跪的蒲团/跪垫）、鼓组、武术、佛祖金光（单独 fx 层，佛的光不是他打理的结果）。

**做旧模型返工 ★（用户四次纠正打出来的完整曲线）**：

1. **均匀降饱和 0.55** → 用户：「本来鲜艳的东西旧了不可能全面均匀变灰，看着很不舒服」。均匀抽灰是**错的做旧模型**：抽掉底色本身，像蒙一层灰玻璃。
2. **改斑驳浮尘，但太密** → 用户：「太过头了」。像撒盐/噪点糊满整件。
3. **浮尘调稀调淡**（大块低频、高阈值、低浓度=薄薄一层）→ 对。坛城红蓝黄在浮尘下鲜活。
4. **佛龛/书柜不该用浮尘** → 用户：「他是木头旧了，应该是区域变色有裂印，不应该是蒙尘」。**做旧必须分材质**：蒙尘(`makePatina`)只对石/织物/铜/沙画；木器要 `makeWeathered` —— 区域性氧化加深发红褐 + 几道顺纹裂印。

**材质分类**（终版）：
- **木器 → `patina:'wood'`**：altar / sutra_shelf / offering_table / khata_rod
- **石·织物·铜·酥油 → `patina:true`(蒙尘)**：thangka / prayer_wheels / torma / dharma_wheel / mani_stones / dungchen / seven_bowls / butter_flower / gau_boxes / vajra_knots / snow_lions / hand_wheel
- **坛城 mandala → 蒙尘**（沙画积浮尘，用时金光在 fx 层醒来）

教训:**「做旧」不是一个统一滤镜,是材质相关的**。木头氧化开裂、织物石器积灰,视觉机制不同,一个 `makePatina` 套所有材质必然有一半看着假。regress 不变（未标 patina 的物件指纹不动）。

先认清这是什么

人生来带一块「缺」。术数不补缺，只让你看清那块缺的形状——所以他们叫「不完人」。
一个不完人 = 一门术数 = 一种解读你的方式。术数会重叠：两个人可以同修一门，但缺的东西不同，说出来的话就不同。

design.html · B8 世界观

这段话是整个产品的技术规格，不只是文案。它规定了三件事，也规定了实现必须分成三层：

世界观说的实现上是什么为什么不能合并
一门术数mingli 引擎的一片叶（liuren / ziwei / cartomancy…）算出来的盘是客观的，谁来算都一样
一块缺解读偏向表——缺勤的人倾向说「该动了」，缺静的人倾向说「该停了」8 门术数被多人同修；同叶不同缺，说的话必须不同
一种性格文案模板——阿云慢半拍爱用「贫道」，白鹭短冷精确到分秒同一个结论，换个人说就是另一句话

而这正是那吉已经在跑的逻辑：真生辰 + 真时刻 → seed 稳定 → 从内容池里按主用神精准抽取，不随机。村民问签只是把它多加两层——缺 与 声。第贰章把这条推广写死。

决策台账

14 条 · 全部已拍 · 沿途不再回头问

「完全线性中途不决策」的意思是：这些岔路现在就选完，写进台账，往后照做。每一条都取质量上限的那个选项，不取省事的那个。

D1
design.html 要不要拆1.7MB 单文件装着圣经 + 引擎 + 素材 + 6 间房。再加 34 间会到 5MB 上下。
拆拆成可构建包：engine/、assets/、rooms/<id>.js、bible/。design.html 降级为构建产物——十道门禁工具全部吃它，不改工具就能继续用。这是 34 间房唯一扛得住的形态，也是按房懒加载的前提。
D2
村子怎么进产品小程序原生 canvas，还是 web-view 装 H5？
原生 canvas御守购买、支付、登录都在小程序里，走 web-view 会把链路切断。引擎不许直接 import wx API——渲染只依赖标准 Canvas2D，另留 H5 构建目标供开发预览与将来非微信渠道。
预设回退：若逐像素命中在 wx canvas 上性能不达标（<30fps），改为构建期烘焙命中掩码位图，仍走原生；不改用 web-view。
D3
村民问签怎么算照搬那吉，还是每人一套？
三层算力层（术数→叶，客观）／偏向层（缺→重排，主观）／声音层（性格→模板）。seed = hash(user_id, villager_id, 年月日)：同一村民同一天答案稳定，换个村民就换个答案。三层分开是硬要求——8 门术数被多人同修，合并就没法「同门不同话」。
D4
御守怎么变成入住
走 commerce v2御守是一类 SKU；履约时写 villager_residency(user_id, villager_id)。NFC 扫码走同一张表，凭据换成 carrier credential。archive/omamori-research/ 那套「载体与身份解耦」的 Adapter 设计正是为此写的，取回来用。
D5
抽不抽 unmei-pg持久化端口独立成 crate？
不抽30 个 trait 方法只会有一个实现、没有测试替身要用这条缝——正是 P1 刚删掉的 2810 行那种死抽象。用例层每个 .await.db()? 就是将来的切口，等真有第二个驱动方再说。本决定终审，不再复议。
D6
两次 /pay 重复扣款实测：应付 19900，实付 39800。
实现幂等键不用「拒绝并发支付」也不用「顶掉旧的」——那两条都是把问题挪个地方。idempotency_log 这张死表本来就是为此建的：客户端带幂等键，同键同参返回首次结果。一次解决重复下单与重复支付两类，并给 order_record 补 amount_paid_minor <= amount_total_minor 的 CHECK。
D7
风控要不要接线引擎完整、9 测试绿、零调用方。
接接在建单与发起支付两处（RFC §3.13）。先只开 log_only——规则照跑、事件照落、一单不拦；后台风控台能看见真实命中率之后再由运营逐条改判定。这不是「以后再说」，是上线策略的一部分，两步都在工序里。
D8
订阅 dunning 阶梯文件头注释写了 T+0/+1d/+3d/+7d，代码一条没有。
实现真接渠道前必须有，否则一次扣款失败就是永久失联。按注释实现：三次重试 → past_due → grace → expired，每步落事件。
D9
对账只比流水号金额对不上也标 matched。
比金额，容差 0对账的意义就是抓金额差异。差一分即 amount_mismatch，进差异清单等人工处理——不做自动容差，钱的事不许模糊。
D10
proto/ 怎么办React 客户端原型，物页面自 commerce v2 起就是坏的。
删真客户端是小程序，proto 与它职能重叠且已腐坏。删掉它同时删掉 ProductPublic 遗留形状的最后一个消费方。不修它的物页面——那要为一个不上线的原型定「列表带不带价」的 API 语义。
D11
admin 那个没人读的 kevy Store
删开一个 Store、写一个 AOF、挂一个 docker volume、记一个环境变量，全为了没人读的字段。连带清 state.rs / main.rs / docker-compose.yml / .env.example / README。
D12
视觉回归 12 处漂移bailu / popo / tenz 三间四姿态全漂。
先判后决逐姿态截图比对：改进则带理由重存基准，回退则修房。必须在拆包之前清零——否则拆包的验收判据（前后哈希不变）建在一个说不清对错的基准上。
D13
34 间房什么顺序
关系密度优先先「在路上」4 位（叙事下一批），再按关系度排。关系是村子活起来的唯一来源——两个有关系的人碰面才有专属对白，孤立角色再精致村子也是死的。全表见第伍章。
D14
一间一验收的铁律与「线性不决策」冲突吗
不冲突房间验收是质量门，不是路线决策——它只回答「这间过没过」，不改变工序单的形状。工序照走，遇门则停、过门则进。唯一需要你出面的只有这一类。

拆包：design.html 变成构建产物

这是阶段 A 的主工程，也是唯一高风险的一步。切成 engine/（39 个函数）、assets/（按房分模块的 prefab 库）、rooms/<id>.js（plan + acts + perform）、bible/（B0–B12 转成文档）。构建脚本把它们拼回一个 design.html。

为什么风险可控：判据是纯机械的——拆完重新构建，regress 的哈希必须与拆前逐个相同。渲染是像素级确定的，改动了什么它一定看得见。

做完了　没有重写成模块，而是按字节切片再原样拼回——这样判据可以比工序单定的那条更硬：拼回来的文件与拆前逐字节相同（两边 sha256 都是 81990f63）。哈希一致只证明渲染没变，逐字节相同证明什么都没变。
树的形状就是工序单要的四分：bible/（页面样式、B0–B12 正文、角色表）· engine/（村图、角色、气泡、校验、布局辅助、渲染管线、两张表的渲染）· assets/（401 件素材按房分文件）· rooms/（六间房的 canvas 脚本）。共 34 个源文件 + manifest.json。
401 个 def 恰好落在 8 段连续区间、零交错，所以按房分文件不用挪动任何顺序。沈砚与丹增各留两个文件（素材是分两批加的，合并就得重排字节）。
两处边界细节决定文件读不读得通：分节要切在横幅注释的第一行，切在下一行的话每个文件都会以半个注释收尾、下一个从注释中间开始；共享绘制原语与 def（） 声明夹在丹增第二批与阿云之间（靠函数提升才能被前面的代码用到），单独成 _prim.js，否则它们会莫名其妙地出现在 assets/ayun.js 顶上。
往返双向都验过：改源码树 → build，产物跟着变；撤回改动 → build，回到原字节。build.js --check 比对产物与源码树，变异测试新增一条「有人直接改了构建产物」，16/16 全抓到。产物开头加了醒目横幅说明它是生成的。
要你知道的代价：这些 .js 是同一个大 IIFE 的片段，单个文件不是合法 JS（括号在别的文件里闭合），要查语法得先 build 再查产物。换掉这个代价就要改成真模块，那意味着放弃「逐字节相同」这条判据——我选了后者优先，因为拆 5MB 单文件时「什么都没变」比「看着没变」值钱得多。你要另一种，说一声。
硬门禁拆前拆后 regress 哈希逐个一致 —— 已达成，且更强：产物逐字节相同

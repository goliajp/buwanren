核心与前提纠正

THE KEYSTONE & A CORRECTION
那吉只验证了「实体引流→小程序」最浅一环。我们要做的是信物＋身份＋内容完整模型 —— 真正的参照系是 Tamagotchi/amiibo × 测测/Co-Star 的合体。
⚑ 前提纠正：标杆「那吉」既不是公仔，也没有身份绑定

实查确认的「那吉」=「那吉·山鬼花钱 NFC 磁吸气囊手机支架（¥89）」。✅ 碰一碰 NFC→微信小程序→命理 吻合。❌ 不是公仔、无数字身份/角色绑定、无养成。小程序功能只有「输入生辰→大模型+随机数→每日五行运势」一项，芯片约 ¥3 卖 ¥89，是玄学情绪商品。背后公司/融资/上线时间未找到（白牌爆款特征）。1 ⇒「无护城河·内容空心」，不是完整模型的范本。

KEYSTONE

基石｜身份与载体解耦

系统里有且仅有一条稳定核心身份 OmamoriIdentity。NFC 的 UID+签名、QR 序列号、链上 token id 都只是指向同一条身份的「载体凭证」。换载体＝换 Adapter，核心身份及其上的绑定/内容/变现纹丝不动。GS1 Digital Link／W3C DID／EU DPP 同此原理。28,29,31

LESSON

把那吉的教训写进设计

  • 无护城河 → 二期上 NTAG 424 DNA 强防伪
  • 内容空心 → 守护养成（对标 Tamagotchi）+ 真人神职
  • toys-to-life 衰退史（Skylanders 暴跌 65%3）＝内容/复购是命门
HARD LIMITS

三个硬约束（环境差异）

  • LINE Pay 日本已死（2025-04 停服）→ 只能 PayPay/Stripe22
  • NFC 唤起 LINE 不保证（iOS 常落 Safari）→ 浏览器兜底必做21,25
  • APPI 要配慮個人情報（信仰＋生辰）→ 事前明示同意、禁止外传10

APPI

要配慮個人情報

姓名+生年月日=个人信息。「信条(含信仰)」是法定要配慮個人情報。取得须事前明示同意，禁止 opt-out 向第三方提供。宗教法人为宗教目的享适用除外，但商业公司须完整遵守。10

ABSTRACTION

「一实体＝一数字身份」的通用抽象

A. GS1 Digital Link＝数据载体完全无关（QR/NFC/RFID/数字水印 编码同一 GS1 标识符，标识符与物理编码分离）28。B. W3C DID + VC / UORA＝把物理对象分散式绑定到数字标识29,30。C. EU DPP＝载体技术无关的持久标识符31。
映射：后端身份键＝规范记录(GS1 URL 或 DID)，NFC UID+CMAC 只是一种载体凭证，QR/RFID/NFT 各自做 adapter 解析到同一记录。NTAG 424 的 Key Diversification(Master Key+UID 派生)让「UID+签名」天然成为后端统一可验证凭证。

卷 05B / DIVINATION ENGINE & AI

命理引擎与 AI 应用

CAST ⟶ INTERPRET ⟶ EXPRESS · LLM AS THE MOUTH, NOT THE ORACLE
核心铁律：「算」与「说」分离。确定性排盘做「算命本身」(可复现/可验证)，知识库做「释义」，LLM 只做「讲人话+个性化」。让 LLM 去推算＝那吉式随机数巴纳姆话术。
⚑ 那吉的根本架构错误（反面教材）

那吉「输入生辰→随机数种子→大模型直接生成文案」：① 没有真实排盘（不可复现，同一生辰多次结果靠随机数飘）② 没有知识库（内容＝大模型臆造的巴纳姆话术）③ 无记忆无个性化。结果是「仅供娱乐」的空壳。
正解：确定性引擎排出真盘（同生辰永远同盘）→ 结构化知识库给释义（可溯源）→ LLM 仅把结构化释义组织成自然语言并按用户语境个性化。LLM 不碰推算逻辑。

命理引擎｜三段式分层（算 → 释 → 说）

A
排盘
排盘 / 起局层Casting Layer — 确定性石头
生辰/抽签/朝向 → 命盘/牌阵/签号。纯计算、确定性、可复现、可单元测试+fuzz、跨项目复用。命门＝天文历法精度。
CastingEngine.cast(input) → Chart（不含任何"含义"，只有结构化盘面）

AI 应用栈｜LLM = 嘴与编排，不是神谕

① 排盘
确定性引擎排真盘(同生辰同盘)
② RAG 检索
命理典籍/释义知识库，引用片段、可溯源、降幻觉
③ LLM 生成
把释义讲人话＋按用户档案/记忆个性化
④ 自检
一致性校验：生成内容不得与排盘/知识矛盾
⑤ 推荐/转介
御守款/参拜/真人祈愿升单(非恐吓式)
↩ 记忆
写回 UserAstroProfile + 向量库，跨会话延续关系
RAG

检索增强 RAG

命理典籍/释义知识库向量化，LLM 引用片段而非凭空生成。三重收益：降幻觉、可溯源(Reading.citations)、风格一致。知识库是钢筋资产，按体系/流派/神社可换。

PROMPT

Prompt 架构

system(人设/口吻/边界：不做医疗·法律·投资断言) ＋ context(排盘结果+知识片段+用户档案+历史记忆) ＋ guardrails(禁恐吓·禁绝对预言)。排盘结果以结构化 JSON 注入，LLM 不得改写盘面数字。

MEMORY

个性化 & 记忆

UserAstroProfile 持久化 + 向量库存历史对话 → 跨会话的持续关系(对标 Co-Star 的"长期陪伴"、Tamagotchi 的养成留存)。这正是那吉无记忆的致命缺口。

ANTI-BARNUM

反巴纳姆

用真实排盘差异驱动内容差异，而非随机数。同一用户同一天结果稳定(确定性引擎)，不同用户结果真不同(盘不同)。可复现是信任与复购的底层。

AGENTIC

Agentic 多步 & 自检

排盘→检索→生成→自检(一致性校验：生成不得与盘矛盾)→推荐。自检是把 LLM 幻觉挡在用户之前的关键闸。多步可编排为 tool-calling agent。

MULTIMODAL

多模态

手相/面相(图像识别，须合规+「仅供娱乐」)、语音解读 TTS(对标 こまいぬAI神社的 AI 语音9b)、生成御守视觉/数字护符图。图像类对准确性主张要尤其克制。

HUMAN-IN-LOOP

真人神职协同

AI 出初稿/初步解读，真人神职审核并主持高客单祈愿(human-in-the-loop)＝信任底座 + 合规 + 高单价。AI 同时辅助神职提效。对标日本 Z 世代「重可信度/愿见真人」14。

MODEL

模型选型

需日语强模型(Claude / GPT / 日本国产 ELYZA·Swallow)。四柱推命等日式知识靠 RAG/微调补足(通用模型对日式命理薄弱)。成本参考：那吉用国内大模型 API ~¥1/次1，毛利空间大。

AI 合规

AI 红线（重点）

霊感商法 高压线：日本特商法/消費者契約法严管「用占卜恐吓推销高价物」(2022 后强化)。AI 绝不能做恐吓式升单(「不买此御守会有灾」)。＋不做绝对预言/医疗/法律断言、「仅供娱乐」声明、AI 生成的「神谕/签文」须标注 AI、神社祈愿走真人不被 AI 亵渎。10

架构落点：CastingEngine / InterpretationEngine 是石头·钢筋(精度命门，大量 audit/校验)；ExpressionEngine(LLM) 是水泥+AI 编排(文案易改、可换模型)。所以「换占卜体系」「换 LLM」「加多模态」都是换 Adapter，与第 05 卷的 RitualEngine 端口一致——AI 本身也是「可换的一环」。

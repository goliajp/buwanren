# 项目规则 · buwanren（卜万人）

## 中文标点必须全角 ★ 反复犯的错

**任何中文内容里的标点一律用全角**，没有例外。这条被用户明确指出过是「你永远都在犯的错」。

| 半角（错） | 全角（对） | |
|---|---|---|
| `,` | `，` | 逗号 |
| `?` | `？` | 问号 |
| `!` | `！` | 叹号 |
| `;` | `；` | 分号 |
| `:` | `：` | 冒号 |
| `...` | `……` | 省略号（中文用六点占两格） |
| `--` | `——` | 破折号（占两格） |
| `()` | `（）` | 括号 |

引号用 `「」`（单层）与 `『』`（内层），不用 `""`。

## 非正式文本结尾不加句号 ★

台词、气泡、短句、列表项、标题这类**非正式文本，结尾不写句号**。句号会让一句话显得生硬、像书面公文，而角色说话不是在念稿。

| 错 | 对 |
|---|---|
| 「看什么看，不会用表格软件怎么了，哼。」 | 「看什么看，不会用表格软件怎么了，哼」 |
| 「还愿。就是还愿。……您别多想。」 | 「还愿。就是还愿。……您别多想」 |

**只去掉结尾那个**——句中用于断句的句号照常保留（见上面第二例）。问号、叹号、省略号表达语气，结尾该留就留。

**适用**：角色台词、气泡文案、界面短句、表格单元格、列表项、标题
**不适用**：正式文档的正文段落、说明性长句

### 适用范围

**必须全角**:
- 角色台词（`say:` 字段、气泡文案、念白）
- 面向用户的界面文案
- 中文设计文档 / 档案 / 编年史
- 中文注释里的自然语句

**保持半角**:
- 代码本身（标识符、字符串键、JSON)
- commit message（英文写作）
- 面向公开仓库的英文文档
- URL、版本号、数字表达式、文件路径

### 自检

写完任何中文台词或文案，扫一遍这个正则，命中即为违规：

```
[一-龥][,?!;:]        # 汉字后面跟半角标点
[,?!;:][一-龥]        # 半角标点后面跟汉字
```

批量体检 `design.html` 里的台词：

```python
import re
s = open('rooms/design.html', encoding='utf-8').read()
bad = [x for x in re.findall(r"say:\s*'([^']{2,60})'", s)
       if re.search(r'[一-龥][,?!;:]', x)]
```

`rooms/design.html` 复检为 431 条 `say` 中 7 条半角逗号 + 3 条结尾句号，

## 先移动网页版，再小程序 ★ 基本工作方法

**任何前端改动，先在移动网页版上做完、验完，再谈小程序**（2026-08-17 用户定）。

理由很直接：小程序那几条门禁写的是「真机 30fps」「一位真实用户从扫码走到问签」，
而真机这一环没法机检——于是每一步都卡在「等人拿手机跑一遍」。
移动网页版把其中能在浏览器里发生的那部分变成**可机检**的，一条命令跑完。

```bash
(cd mini && npm run build:engine)   # 引擎产物，两边共用
bash web/run-verify.sh --shots=/tmp/s  # 组装 + 起服务 + 动线跑一遍，留截图
```

**组装那一步归 `run-verify.sh` 自己管**，不要在外面先手敲一遍 `build.mjs`。
它以前在调用方那边，于是改完 `web/runtime/` 直接跑验证，量到的是**上一次构建**
的结果——一整轮绿，说的却是旧代码的事。这种失效长得跟数据一模一样。

### 它是镜像，不是第二个产品

`web/` 里**没有任何页面代码**。页面的 `.ts` / `.wxml` / `.wxss` 就是
`mini/miniprogram/pages/**` 那些文件本身，引擎与房间也是同一批产物。
`web/` 只有三样东西：`runtime/`（`Page()` / WXML→DOM / `wx.*` 垫片）、
`build.mjs`、`verify.mjs`。

平台差异**只允许存在于一个地方**：`rooms/host/`。共用逻辑在 `mount.js`，
两个平台各一支（`wx.js` 27 行、`web.js` 29 行），加起来就是全部差异。
差异越小，「在网页版上验过」这句话越值钱。

### 三条铁律

1. **垫片遇到不认识的东西必须抛，绝不跳过。**
   跳过会渲出一个少了几块、看着却完整的页面，于是「验过了」变成空话——
   那比没有镜像更糟，因为它给的是错的信心。
   不认识的标签／指令／事件都抛，抛出来就去实现掉。

2. **只有真机才有的能力，抛，不给空实现。**
   `wx.login` / `wx.scanCode` / 选头像这些，浏览器里没有对应物。
   空实现会让这一步在网页上「成功」而真机上根本没发生。
   ——反过来，浏览器**真有**的（加速度计走 `devicemotion`）就要真接上，
   摇卦那一页在手机浏览器上是可以真验的。

3. **与真机的差别，写在代码里。**
   差别本身不是问题，被当成一样才是。每个垫片方法后面注清楚它在浏览器里
   真的做了什么、与真机差在哪。

### 验到什么程度算数

`verify.mjs` 默认**拦掉 `/v1/**` 喂固定响应**——后端要 Postgres，本机不一定起着。
所以它验的是**前端这一侧**：页面 → `services/api.ts` → `wx.request` → `fetch`
整条真路都走，只有最后一跳是假的。字段与状态码对不对得上后端，由
`scripts/check-api-shape.py` 另外机械核对。要打真后端就 `--api=<base>`。

### 打真后端（更值钱的那一档）

本机的 Postgres 在 **docker 里、端口 6032**（不是默认的 5432——我用 `pg_isready` 查
默认端口，误判过一次「没跑」）。后端跑起来之后可以让镜像打它：

```bash
(cd backend && DATABASE_URL='postgres://unmei:unmei_dev_pwd@localhost:6032/unmei' \
   UNMEI_API_BIND=127.0.0.1:6028 UNMEI_CACHE_DIR=/tmp/unmei-cache \
   MINGLI_API_BASE=http://127.0.0.1:6027 cargo run -p unmei-api &)
bash web/run-verify.sh --api=http://127.0.0.1:6028
```

这一档跑的是**真链**：匿名登录 → 扫御守入住 → 问签 → 进屋。
匿名登录打的是 `/v1/auth/anonymous`，**不需要 wx.login**，所以镜像能真的登录。
只有扫码那一跳由验证脚本显式桩掉（`__wxStub`），凭据是往库里种的真凭据、
走的是真的 `/v1/omamori/scan`。

**这一档抓到过假服务端抓不到的东西**，各举一例：
- 垫片把 `content-type` 与调用方的 `Content-Type` 当成两个键，`fetch` 合并成
  `application/json, application/json`，服务端 415——**每个 POST 都发不出去**。
  假服务端不看 content-type，所以只有真后端会红
- 村主屏没接 `onAuthReady`：匿名登录是异步的，冷启动时 `onShow` 抢在 token 之前
  拿 401，而且此后再也不重取。假服务端不认 token，怎么都给 200

后端测试也在本机跑得动，比等 CI 快得多：
`(cd backend && TEST_DATABASE_URL='postgres://unmei:unmei_dev_pwd@localhost:6032/unmei_test' cargo test)`

**库名是 `unmei_test`，不是 `unmei`。** 测试会往 `price_book` 插行，
跟跑着的 API 共用一个库时，那些行会把下一轮 `verify-semantics` 的
「混币种必须被拒」前提冲掉 —— 那条断言就偶发地红一次，
而偶发的红比常红更糟：它让每一次真红都能被当成噪音。
`gates.sh` 会幂等地建这个库，来龙去脉见 `docs/FINDING-2026-08-22-shared-test-db.md`。

**CI 上这一档也跑**（2026-08-23 起，`mini.yml` 的 `mirror-api` job）：
起 Postgres、编 `unmei-api`（它启动时自己跑 migrations 与 seed）、
等端口真有人应答，再让镜像打它。
在这之前 CI 只跑假服务端那一档——**65 个处理器里只碰得到 18 个**，
因为整条真链都挂在「有真后端」上。现在是 **56 个**。
上面列的那两个 bug 正是这个差额藏住的。

**再往上一档：带排盘服务**。用神、盘面由 `mingli`（另一个仓库）算，
它跑起来之后加一个参数，「建本命」那条会一路验到用神：

```bash
bash web/run-verify.sh --api=http://127.0.0.1:6028 --mingli=http://127.0.0.1:6027
```

**本机不用记得加这个参数**：`run-verify.sh` 看到 6027 上有东西应答就自己接上
（判据是「有没有人应答」，不是某条路径给不给 200——拿 `/health` 当探针
在这个仓里已经误判过两次）。

它值得自动接，是因为**没接的时候验的是「还没建本命」那个状态**，
而真实用户在那个状态里只待一分钟。2026-08-23 头一次接上，
当场量出 `home` 超 185px、`natal` 超 180px，另有两条断言从来没执行过
（一条点的是罗盘搬家后就不存在的「转一下」）——它们都躲在
「有本命」那一支里，靠从不运行而保持绿色。

CI 上仍旧没有排盘服务，那一段照旧**明说跳过**，不计入通过。
**不给它做假的**：假服务会按我以为的形状回话，
而 2026-08-18 抓到的正是「我以为的形状」错了（性别发 `M`，它只认 `male`；
问签发 `natal_id`，它只认生辰字段）。这两处让建本命对每个用户都失败、
84 条问签里 80 条的盘是空的，而假服务会把这种错原封不动地盖住。
详见 `docs/FINDING-2026-08-18-*.md`。

**仍然只有真机能验的**：30fps、微信登录（升级成微信账号那条）、扫码本身、
选头像、支付。这些在网页版上会**抛**，不会假装通过。

## 分支与合并 ★

**不开 PR，走 branch merge**（2026-08-17 用户定）。

开个分支做事，做完在本地合回 `develop` 再推：

```bash
git checkout -b <topic>
# ……做事、提交……
git checkout develop && git merge --no-ff <topic>
# 合并前把门禁跑一遍，合并本身也可能引入问题
git push origin develop && git push origin --delete <topic>
```

推之前查 **全部** workflow，不是你正在盯的那一条：

```bash
bash scripts/ci-status.sh        # 每条 workflow 对当前 commit 成不成立
```

带 `paths` 过滤的 workflow 不会在每个 commit 上跑，所以「最后一次绿」未必对
当前 HEAD 成立 —— 脚本会顺带检查那之后它关心的路径动没动过。
(2026-08-17:`backend` 连红四次没人看见，因为我只盯着自己写的 `rooms`。)

合并前必须在**合并后的 develop 上**跑一遍门禁，不是只在分支上跑过就算：

```bash
bash scripts/gates.sh            # 全部（要 Postgres）
bash scripts/gates.sh --quick    # 跳过慢的那三支
```

清单在脚本里，不在这段文字里——写成散文会过时，写成代码不会。
它**不在第一个失败处停**，全跑完报总账。

顺带一条：**别把门禁接管道**。`python3 scripts/check-punct.py | tail -1`
拿到的是 `tail` 的退出码，红了也看着像绿的（2026-08-18 我就这么把一次
真失败当成通过提交了）。`gates.sh` 自己判退出码。

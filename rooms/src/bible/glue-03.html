角色设计规范

以图鉴设计为权威基准（正面）。每角色 大 / 中 / 小 × 正 / 左 / 右 / 背·大在前，行走动画两帧步伐循环：正 = 向下走 · 背 = 向上走 · 左右 = 横走（斜向亦用左右，仅垂直上下用正 / 背）。用途：大 = 首页 UI · 中 = 屋内 / 图鉴 / 页面 UI · 小 = 村子。比例：小 2 · 中 3 · 大 4 px/格。此表为单一数据源，游戏 sprite 与之对齐。

— 角色
LYING POSES卧姿 · 与正/左/右/背同级的一档,睡觉行为专用
三向

仰卧(sleepv / sleepv2)与侧卧(sleepside / sleepside2)。侧卧只做一侧,另一侧由 flip 得到,与行走的左右一致。第二帧仅差被沿起伏一格 —— 呼吸要轻,幅度大了会变成抽动。

规格

12 列 × 30 行 · scale 8 → 96×240px。头占 8 行,与站姿头高一致;身长约为床长的 62%,躺上去才像占着这张床而不是坐在一小块上。

解剖顺序

发顶 → 鬓角 → 额 → 闭眼 → 鼻梁 → 嘴 → 下巴 → 颈 → 肩 → 被沿 → 被面。侧卧另加:后脑朝一侧、只露半张脸、被下身形窄一列(侧身占地本就窄)。

用法

睡在家具上时必须 attach 到宿主并给足 zBias,否则会被它正躺着的那件家具盖住。行为侧用 sleepAt 声明躺位,寻路终点留在床外 —— 人不该在床上走。

注意

ACTORS 通过 getter 引用 POSES,姿态只需在 pdef 处写一次 —— 早期的快照写法已废弃。但姿态名写错仍会静默回退成 stand,不报错:改名或新增后要把键取回来确认命中真图,别只看页面有没有报错。

猫 · 绘制规范

像素密度必须与人一致。阿云 scale: 8,猫也必须是 8 —— 颗粒不同大,两者就不像一个世界里的东西。这条优先于一切构图考虑。

不按真实比例。真猫约人的 1/3 高,在 scale 8 下只剩 5 格,那个分辨率画不出可辨识的猫 —— 头身腿会糊成一条。取像素游戏的通行做法:放大到约人的 2/3(坐姿 12 格 ≈ 96px),让剪影有地方成立。

剪影四要素,缺一就不像猫,加再多细节也救不回来:

  • 耳 — 两只分开的实心三角,中间留出头顶。写成孤立描边点(..K...K.)是最常见的失败
  • 颈 — 头与身之间必须收窄一格,否则是个方块不是动物
  • 尾 — 长度接近体长,沿一侧上翘,末端出轮廓。没有尾巴的猫是老鼠
  • 腿 — 站/走姿两腿之间必须留出空隙,让人看得出有四条腿

配色(共用阿云调色板):O 橙毛 · C 深橙耳内 · E 绿眼 · P 粉鼻 · W 胸口与前爪白 · K 描边。白色只用在胸口、嘴周、爪尖 —— 这三处是橘猫的天然分布,乱撒会变成花猫。

落地点用 footMode: 'bottom',按 sprite 自身底边中心。猫的姿态尺寸差异大(坐 12 格高、卧 7 格高),固定 foot 必然让其中一个悬空。

NAMING命名规范 · 三条,开新房前先对照
① 画布

<角色id>Canvas。角色 id 见 B9:ayun / tao / popo / tenz。
房间的画布跟着住在里面的人走,不叫 roomCanvas 也不按序号排 —— 36 间村民屋一旦按序号命名,改动时没人认得出动的是谁家。

② 姿态

{动作}{方向}{帧号},方向只用 side / front / back。
侧走三帧按时序编号,循环走 1 → 2 → 3 → 2:walkside1(触地)· walkside2(过渡)· walkside3(另一侧触地)。正走 walkfront1/2,背走 walkback1/2,站姿 standside / standback。
不留别名。walkmid / walk1 / walkdown1 这类旧名一律换掉 —— 两套名字并存,第三间房就会长出第三套。
例外:stand 不带方向,它是引擎的兜底姿态(actorSprite 找不到姿态时回退到它),按正面理解。

③ 素材

<房间前缀>_<物件>,如 tao_bed / tao_swing。跨房通用的件用 scope: 'generic' 标注,前缀保留它出生的那间房(fromRoom)。

尚未收敛

规范是全局的,但下面几处还没改到位,开工前别照抄它们:
· 婆婆 / 丹增两间仍是 walk1 / walk2 / walkmid,随该房的素材化一起改;
· 动物姿态走物种前缀(cwalk1 猫 · dsw1/ddn1/dup1 金毛 · rhop1 兔),其中金毛的 sw/dn/up 其实就是 side/front/back;
· 卧姿 sleepv 的 v 是体位不是朝向,不在 side/front/back 之列。

改名怎么验

姿态查不到时 actorSprite 静默回退到 stand,不抛错 —— 所以改名之后光看页面不报错说明不了任何事。逐个取一遍 window.AYUN_POSES / TAO_POSES 的键确认都在,再跑 tools/regress.js check 比指纹。

POSE AUTHORING新增姿态的两条硬规则 · 全角色适用,不限卧姿
① 头部整段复用

新姿态不得另画头,须从既有姿态逐行照搬:朝上/朝前用 stand 的头,朝侧用 standside 的头,只新画脖子以下。
为什么:卧姿初版我自画了一个头 —— 脸更窄、眼鼻换了字符、没有发髻和鬓角,床上躺的看着像另一个人。角色一致性会在每个自画的新姿态上流失一点,而这种流失不会报错,只会越来越不像。

② 身体对齐头轴,宁可加宽

复用头部后,身体必须对齐该头的中轴。站姿头占 2–11 列(轴 6.5)、侧站头占 1–9 列(轴 5),各自不同,不能想当然按 sprite 居中。
宽度不够时加宽身体,不要挪头 —— 挪位是让被子迁就头,加宽是让被子把头包住,后者才是被子该有的样子。
容差:半列(4px @scale8)的偏移就足以读成歪脖子。

③ 侧向一律朝右

所有侧向 sprite(走/站/跑/跳)一律画成面朝右。房间给的 flip 统一表示「朝向行进的反方向」,即 flip = 目标在左。
为什么:基准朝向曾经发散 —— 阿云朝右、猫与兔朝左,金毛也朝左却按朝右的规则写 flip,于是走路方向整个反过来。猫和兔当时是「基准反了 + flip 也反了」两处错误互相抵消,看着对,实则随时会被下一个人改坏。
校验方式:不许目视判断 —— 用 tools/facecheck.js 或量眼睛像素的横向质心(>0.5 即朝右)。此处的注释本身就曾写着「默认朝左」而实际朝右,照着注释改只会改反。
兜底:确实无法重画的素材可在角色资源上声明 baseFacing:'left',引擎补一次镜像;但这是例外,不是许可。

④ 只需写一处

角色资源现在引用window.AYUN_POSES(即房间的 POSES),不再各存一份快照 —— 新姿态在 pdef 处写一次即可,ACTORS 自动可见。
此前是拷贝式,漏写一边会静默回退成 stand:不抛错、不告警,只是人物忽然站着"躺"在床上。该陷阱已从根上移除。
